# 私家版リバインダー（shikaban-rebinder）

自分で購入した本を、自分の iPad で撮った**画面収録またはスクリーンショット**から、
自分で読むための PDF に製本する単一 HTML アプリ。

**処理はすべてブラウザの中で完結し、通信は一切しない。** 画像・PDF・記録はどこへも送信されない。
サーバーもアカウントも要らない。開いた時点で全機能が手元にある。

→ https://ryomiyagawa185-crypto.github.io/shikaban-rebinder/

Safari の「共有 → ホーム画面に追加」でアプリとして常駐する。

---

## 境界（このアプリがやらないこと）

| やること | やらないこと |
|---|---|
| 正規アプリが画面に**通常表示している内容**を、OS標準のスクリーンショット／画面収録で**利用者自身が撮る**。<br>その画像を切り抜き・並べ替え・PDF化する。 | DRM の解除・復号、鍵やトークンの抽出、アプリ内部ファイル／キャッシュ／通信の解析、<br>キャプチャ防止の回避、他人のアカウントからの取得、できた PDF の共有・配布・アップロード。 |

画面が黒・白・一様（保護表示）になった場合、**回避せずその場で停止する**。アプリはこの判定を自動で行い、
検出したら製本を止める。回避手段は実装していないし、今後も実装しない。

このアプリは**適法性を判定しない**。購入済み・個人利用という事情だけで、あらゆる複製が当然に
許されるとは限らない。各サービスの規約と適用される法令の確認は利用者が行うこと。

## 撮り方（iPad）

1. 通知と自動ロックを止める（設定 → 画面表示と明るさ → 自動ロック → しない）。
2. 正規アプリに**自分で**ログインし、購入済みの本を開く。
3. **ページ送り表示にする**（スクロール表示だと1画面＝1ページにならない）。文字サイズ・余白・向きを固定する。
4. コントロールセンターから画面収録を開始する。
5. **各ページで約1秒静止**してからめくる。静止が短いと取りこぼす。
6. 最終ページで数秒静止して収録を終える。

スクリーンショット方式（1ページ1枚）も使える。AssistiveTouch のフローティングボタンに
スクリーンショットを割り当てると1タップで撮れる。

## 工程

| 工程 | 内容 |
|---|---|
| 一 境界の確認 | 5項目に印が付くまで以降を開かない |
| 二 素材の取り込み | 画面収録（動画）または スクリーンショット群。書名・綴じ方向・**上限ページ数（必須）** |
| 三 試験抽出 | 先頭3ページだけ走査。保護画面判定・見え方の確認。**承認するまで本処理へ行かない** |
| 四 ページ抽出 | 静止区間の**末尾フレーム**を1ページとして採用。重複候補に印、保護候補は自動で除外 |
| 五 版面の整形 | 余白の自動検出＋手動調整、見開き分割、長辺画素数・画質 |
| 六 製本と取り出し | ブラウザ内で PDF を組む（JPEG を DCTDecode で直接埋め込む） |
| 七 検品記録 | 抽出数・採用数・重複・保護・停止理由・設定・ページ別ハッシュを JSON で出す |

## 走査の設計（実測で決めた3点）

1. **標本の時計は `requestAnimationFrame`。** `requestVideoFrameCallback` は映像が画面に提示された時だけ
   発火するため、DOM外の `<video>` では毎秒1回しか回らない（rAF は60回）。実測で静止中の差が 40 に達し、
   1ページも拾えなかった。走査中の映像は画面に置く。
2. **静止は「サンプル数」でなく「映像内の秒数」で判定。** 端末やファイルで標本密度が変わるため、
   回数で決めると環境依存になる。既定 0.5 秒。
3. **再生倍率は自動で落とす。** 復号が追いつかないと標本が疎になりページを飛ばす。密度（回/映像秒）を
   常時測り、`3 / 静止秒数` を割ったら倍率を半分にする（下限 0.5 倍）。

ページの弁別は 8×8 平均ハッシュではなく**輝度64×64格子の平均絶対差**で行う。8×8 は文字組のページに
対して粗すぎ、別ページ同士の距離が閾値と衝突した。差し替え後の実測は 同一 0.18〜0.21 / 別 19.9〜20.5。

長さ不明の収録（`duration` が `Infinity`）は、走査前に末尾へ一度シークして実長を確定させる。
これをしないと再生が途中で `ended` になり最後のページを落とす。

## 検証

Chromium で合成素材を通した結果。

| 経路 | 素材 | 結果 |
|---|---|---|
| スクリーンショット | 10枚（5枚目=4枚目の複製・7枚目=真っ黒） | 9ページ／重複1検出／保護1を自動除外 |
| 画面収録 | 9ページ・各1.2秒静止 | 9ページ（倍率2.1倍へ自動調整） |
| 画面収録 | 同上の7枚目が真っ黒 | 6ページで停止（保護検出） |
| 画面収録 | 3ページ・末尾に長い静止 | 3ページ（末尾を落とさない） |
| 余白の自動検出 | 上下12%・左右11%の余白 | 11/11/10/8% |
| PDF | 9ページ | xref整合・埋め込みJPEGがバイト一致・1230×1560で描画 |

iPad の Safari 実機での疎通は、工程三の試験抽出が兼ねる。

## 限界

- **OCR は無い。** 生成されるのは画像 PDF。本文検索・コピーはできない。
- **メモリ。** iPadOS の Safari はタブあたりの上限が厳しい。上限ページ数の既定 300 は安全側。
  長い本は章ごとに分けて収録する。
- **走査中は画面を消さない。** iPadOS がバックグラウンドの処理を止める。
- **走査は実時間がかかる。** 倍率を自動で落とすため、復号が重い端末では収録長に近い時間がかかる。
- **スクロール表示には対応しない。** ページ送り表示が前提。
